# Design — ai-brief

## Overview

`backend/brief.py` is a small, dependency-light module. The brief is generated
by Amazon Nova 2 Lite via the Bedrock Converse API (model chosen by the
`BEDROCK_MODEL_ID` environment variable) and cached in
`backend/cache/brief.json`. Bedrock access is optional and always has a safe
fallback to the cached brief, so the function is runnable with no AWS setup and
in tests; the shipped cache was generated by Amazon Nova 2 Lite (source
"bedrock").

## Components

### `_get_client()`
Lazily imports `boto3` inside the function so tests can monkeypatch it and so a
missing boto3 is a handled fallback, not an import error. Builds a
`bedrock-runtime` client using `AWS_REGION` (default `us-east-1`). Raises if
boto3 is missing or `BEDROCK_MODEL_ID` is unset (caller treats this as a
fallback trigger).

### Prompt building
- `SYSTEM_PROMPT` — fixed system text: write as a short internal note for harbor
  authorities, use ONLY the provided JSON, exactly 3 sentences (detection /
  per-vessel response with the compliance percentage / recommended action naming
  the non-complying vessel), write speeds as "16 to 10 knots" (never arrows),
  copy `compliance_display` exactly, and end sentence 3 noting that vessel data
  is simulated and the clip is a synthetic demo clip.
- `_user_message(detection, compliance)` — serializes the two dicts as JSON for
  the user turn.

### Bedrock call
`converse()` is called with:
- `modelId=BEDROCK_MODEL_ID` (Amazon Nova 2 Lite)
- `system=[{"text": SYSTEM_PROMPT}]`
- `messages=[{"role": "user", "content": [{"text": _user_message(...)}]}]`
- `inferenceConfig={"maxTokens": 300, "temperature": 0.2}`
The text is read from `response["output"]["message"]["content"][0]["text"]`.

### Output validation (`_validation_failure`)
Bedrock output is accepted only when every check passes; otherwise a warning is
logged naming the failed check and the cache is used. The checks are:
- non-empty;
- exactly 3 sentences (`_count_sentences`, which ignores decimal points);
- contains every phrase in `REQUIRED_BRIEF_PHRASES` — "right whale up-call",
  "10 nm", "simulated" (case-insensitive);
- contains the compliance percentage written as `f"{pct:g}%"` (e.g. `75%`);
- contains no substring in `FORBIDDEN_BRIEF_SUBSTRINGS` — `->`, `→`, or `"`;
- contains no digit glued directly to a letter (e.g. `at75`).

### `generate_brief_result(detection, compliance) -> dict`
Tries Bedrock. Returns `{"brief", "source": "bedrock"}` only if
`_validation_failure` returns `None` (all checks above pass). On any Bedrock
failure, or any failed check, returns `{"brief": <cache text>, "source":
"cache"}`.

### `generate_brief(detection, compliance) -> str`
Contract function: returns `generate_brief_result(...)["brief"]`.

### Cache helper
- `_read_cache()` reads `backend/cache/brief.json` and returns its `brief`.
  `main()` overwrites the cache only when fresh output has `source == "bedrock"`.

### `build_demo_input() -> (detection, compliance)`
Matches the structure.md Demo canon: detection at H-2, 10 nm zone, 4 vessels in
zone (Nordic Tide 16->10, Harbor Queen 22->10, Blue Fin II 11->9, Cape Runner
19->17 not_complying), compliance 75%. It reads both `confidence` and the
2-decimal `confidence_display` (e.g. "1.00", never a percentage) from
`ml/demo_result.json`; neither value is hard-coded in source. If that ML-owned
file is absent, `build_demo_input()` raises a clear `FileNotFoundError` naming
the path and telling the user to run `python -m ml.cache_demo` — there is no
spectrogram fallback.

## Error handling

All Bedrock/boto3 errors are caught broadly and funneled to the cache fallback;
the blind catch carries a `# noqa: BLE001` with a reason, matching repo
conventions. The cache read is the last line of defense and is always present.

## Testing

`tests/test_brief.py` monkeypatches `_get_client` / the client's `converse` to
simulate failures and fake outputs. It covers: Bedrock raising falls back to
cache; output missing "simulated" falls back; a valid fake brief is accepted as
`source == "bedrock"`; output using `->` arrows falls back; output with a digit
glued to a letter ("at75%") falls back; output missing the exact `75%`
compliance figure falls back; the cached brief mentions "simulated" and
"synthetic"; and `build_demo_input()` confidence equals the ML demo result.
`backend/__init__.py` exists, so no conftest is added unless imports fail.

## Property-based tests

`tests/test_properties.py` (Hypothesis) adds randomized coverage for the brief
output validation:

- **R3 (fallback / honesty checks).** For random text, any string containing a
  digit glued directly to a letter (e.g. "at75"), and any string containing
  "->", is rejected by `_validation_failure` (i.e. it returns a non-None reason,
  so `generate_brief_result` would fall back to the cache). The shipped
  `backend/cache/brief.json` passes validation against the demo compliance from
  `build_demo_input()`.

"Rejected" is asserted as `_validation_failure(...) is not None`; the specific
failing check may vary because the checks run in order and return the first
failure. No property found a counterexample.
